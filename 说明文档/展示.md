## 1. 平台整体介绍

### 1.1 平台定位与价值

**讲稿内容**：

各位评委老师好！今天我为大家演示"数治骑迹"平台，这是一个面向共享电动自行车超速行为时空演化与预警的警务决策支持系统。

平台基于"数据-行为-风险-预警"四位一体理论框架，将复杂的空间统计算法转化为一线民警可直接执行的工作指令，实现从"事后应对"到"事前预防"的治理模式转型。

**对应程序文件**：
- 主界面：`backend/app/templates/index_v4.html`
- 应用初始化：`backend/app/__init__.py`
- 配置文件：`backend/app/config.py`

**动图插入位置1**：展示平台主界面整体布局
- 操作：打开浏览器访问 `http://127.0.0.1:5000/`
- 动图内容：展示平台标题"🚔 数治骑迹"、顶部操作栏、各功能模块布局

---

### 1.2 平台架构概述

**讲稿内容**：

平台采用轻量化的Runtime Pipeline架构，实现了零数据库依赖的完整分析流程。系统分为四个核心层次：

1. **数据层**：支持CSV格式轨迹数据上传，自动识别多种字段命名方式
2. **分析层**：多模型融合分析（Moran's I、Getis-Ord Gi*、Mann-Kendall）
3. **可视化层**：地图、图表、报告多端统一展示
4. **反馈层**：用户反馈与策略优化闭环

**对应程序文件**：
- Runtime Pipeline：`backend/app/services/runtime_pipeline.py`
- 架构说明：`流程图/数治骑迹平台全要素架构机制图_介绍.txt`

**动图插入位置2**：展示平台架构流程图
- 操作：打开架构机制图
- 动图内容：展示数据流转过程（数据上传→分析→可视化→反馈）

### 9.1 Runtime Pipeline轻量化架构

**讲稿内容**：

平台的核心创新是实现了完全脱离数据库的轻量化Runtime Pipeline架构。所有中间结果和最终成果存储在`outputs/runtime/`目录下，包括轨迹点CSV、热点GeoJSON、分析摘要JSON等，实现了零数据库依赖的完整分析流程。

**对应程序文件**：
- Runtime Pipeline核心：`backend/app/services/runtime_pipeline.py`
- 数据文件：
  - `outputs/runtime/trajectory_points.csv`：清洗后的轨迹点数据
  - `outputs/runtime/hotspot_areas.geojson`：热点区域GeoJSON
  - `outputs/runtime/risk_grid_summary.geojson`：网格汇总GeoJSON
  - `outputs/runtime/analysis_summary.json`：分析摘要JSON

**讲稿内容**：

**讲稿内容**：

- 风险分级：Gi* Z值 ≥ 2.58为高风险，1.96~2.58为中风险，1.65~1.96为低风险
- 演化模式：基于Mann-Kendall趋势检验识别17类时空模式

平台实现了从数据上传、风险识别、预警推送到用户反馈的完整业务闭环，形成了"事前预警—事中干预—事后评估"的主动防控体系。

**业务流程**：
1. **数据上传**：CSV轨迹数据上传，自动清洗和标准化
2. **风险识别**：多模型融合分析（Moran's I、Gi*、Mann-Kendall）
3. **可视化展示**：地图、图表、报告多端统一展示
4. **指令生成**：算法结果自动转化为可执行指令
5. **用户反馈**：现场反馈与策略优化闭环

**对应程序文件**：
- 完整流程：`backend/app/services/runtime_pipeline.py`（`run_full_analysis`方法）
- 业务闭环：`backend/app/services/feedback_service.py`（反馈数据关联热点区域）

**技术亮点**：
- 自动化流程：从数据上传到指令生成全流程自动化
- 数据验证：用户反馈验证分析结果准确性
- 持续优化：基于反馈数据优化分析参数和策略建议

### 10.2 核心模块功能说明

**讲稿内容**：

下面我详细说明各个核心模块的功能和作用。

#### 10.2.1 后端服务层（backend/app/services/）

**Runtime Pipeline（runtime_pipeline.py）**：
- **核心地位**：整个平台的数据流转核心，实现零数据库依赖的完整分析流程
- **主要功能**：
  - 数据清洗：字段识别、漂移点剔除、缺失点截断、地图匹配
  - 网格化：将轨迹点聚合到500m×500m网格，计算超速次数、轨迹数量等指标
  - 空间统计：调用Moran's I、Getis-Ord Gi*、Mann-Kendall算法
  - 热点识别：基于Gi* Z值自动分级（高/中/低风险）
  - 演化模式：识别17类时空模式（振荡热点、新增热点等）
- **输出文件**：所有中间结果和最终成果存储在`outputs/runtime/`目录

**指令化转译服务（interpretation_service.py）**：
- **核心创新**：将算法结果转化为可执行指令
- **主要功能**：
  - 基于Moran's I值、热点数量、趋势类型生成分级指令
  - 三级预警：红色（紧急）、黄色（预警）、蓝色（常态）
  - 策略建议：结合热点类型生成差异化应对策略

**图表生成服务（chart_generator.py）**：
- **主要功能**：使用matplotlib生成高质量可视化图表
- **图表类型**：综合仪表盘、趋势折线图、时段分布图
- **输出格式**：PNG图片文件，支持中文字体显示

#### 10.2.2 空间统计算法层（spatial_analysis/）

**Moran's I分析（moran_analysis.py）**：
- **算法实现**：全局Moran's I、局部LISA聚类
- **技术特点**：KNN权重矩阵（k=5）、行标准化、双实现机制
- **输出结果**：Moran's I值、LISA聚类标签（5类模式）

**Getis-Ord Gi*分析（hotspot_analysis.py）**：
- **算法实现**：Getis-Ord Gi*统计量计算
- **风险分级**：Z值≥2.58为高风险，1.96~2.58为中风险，1.65~1.96为低风险
- **输出结果**：Gi* Z值、风险等级、热点多边形

**Mann-Kendall趋势分析（trend_analysis.py）**：
- **算法实现**：Mann-Kendall非参数趋势检验
- **输出结果**：趋势类型（上升/下降/无趋势）、演化模式分类（17类）

#### 10.2.3 前端界面层（backend/app/templates/）

**模块化设计**：
- 主页面（index_v4.html）整合所有功能模块
- 8个子模块文件（index_v4_01到index_v4_08）实现功能分离
- 动态加载机制，支持按需加载和独立开发

**交互功能**：
- Leaflet地图：支持缩放、平移、点击查看详情、图层切换
- 图表生成：支持时间范围筛选、自定义日期、图表下载
- 指令展示：三级预警指令、详细指令、策略建议

### 10.3 数据流转路径

**讲稿内容**：

平台的数据流转路径清晰明确，从数据上传到最终可视化展示，每个环节都有明确的输入输出。

**完整数据流转路径**：

1. **数据上传阶段**：
   - 用户上传CSV文件 → `backend/app/routes/upload.py`
   - 文件解析 → `backend/app/services/data_upload.py`
   - 数据清洗 → `backend/app/services/runtime_pipeline.py`（`_prepare_geodataframe`）
   - 存储 → `outputs/runtime/trajectory_points.csv`

2. **分析处理阶段**：
   - 触发分析 → `backend/app/routes/analysis.py`（`POST /api/analysis`）
   - 网格化 → `backend/app/services/runtime_pipeline.py`（`_aggregate_to_grid`）
   - 空间统计 → `spatial_analysis/` 各算法模块
   - 结果存储 → `outputs/runtime/analysis_summary.json`、`hotspot_areas.geojson`等

3. **可视化展示阶段**：
   - 图表生成 → `backend/app/services/chart_generator.py`
   - 地图数据 → `backend/app/routes/visualizations.py`
   - 前端展示 → `backend/app/templates/index_v4_*.html`

4. **指令生成阶段**：
   - 指令转译 → `backend/app/services/interpretation_service.py`
   - 指令展示 → `backend/app/templates/index_v4_05_instructions.html`

5. **反馈闭环阶段**：
   - 反馈提交 → `backend/app/routes/feedback.py`
   - 反馈存储 → `outputs/runtime/feedback_records.json`或MySQL数据库
   - 策略优化 → 基于反馈数据优化分析参数
